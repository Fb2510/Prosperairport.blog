软路由换了 DNS，浏览器还在用哪一个？

阿旺2026-11-12— 次阅读
软路由与排障

软路由换了 DNS，Windows 能查到网站地址，Firefox 打开同一个网站却还报错。先查 Firefox 有没有自己发 DNS 请求。DNS 帮你把域名查成 IP 地址，DNS over HTTPS（简称 DoH）则把这一步查询放在加密的 HTTPS 连接里。浏览器开启自己的 DoH 后，查地址时可能走另一条路。下面用 Windows 和桌面版 Firefox 举例。Mozilla 的 DoH 说明

先看命令行问了谁

在 Windows 的 PowerShell 或命令提示符里运行 nslookup example.com，把 example.com 换成出问题的网站域名。只填域名时，nslookup 使用默认 DNS 服务器。输出开头的服务器地址可以拿来和你预期的地址对照。若软路由负责接收 DNS 查询，可以再运行 nslookup example.com 192.168.1.1，把示例地址换成你的软路由实际提供 DNS 服务的地址。微软的 nslookup 用法

如果两个命令都返回了地址，说明这两次查询得到了回答。软路由如果使用 dnsmasq，回答可能来自它的缓存，也可能是它转问上游服务器后拿到的。即使刚换过上游，电脑看到的仍可能是软路由原来的地址。dnsmasq 的缓存和转发说明

再看 Firefox 有没有自己查

  1. 在 Firefox 打开「设置 → 隐私与安全」，往下找到「DNS over HTTPS」。记下状态和保护级别，必要时点「高级设置」。状态显示为活动，表示 Firefox 正在使用加密 DNS 功能。默认保护会根据当前网络和策略决定是否启用，也可能回退。关闭时，Firefox 的这项加密 DNS 功能停用。这里的状态适合判断整体设置，单个域名要再看下一步。Mozilla 的设置与状态说明
  2. 在普通窗口新开一个标签页，输入 about:networking#dns。这是 Firefox 自带的 DNS 诊断页。先找出问题的域名。如果想尽量排除旧结果，可关闭目标网站的标签页，在诊断页清除 DNS 缓存，再用普通标签页访问目标网站，回到诊断页查看。有时浏览器会复用已有连接，刷新页面也可能暂时没有新的 DNS 记录。Firefox 的 DNS 诊断页源码
  3. 找到对应域名后看 TRR 一栏。TRR 是 Firefox 给自己的 DoH 实现起的名字。true 表示这条缓存记录来自 Firefox 的 DoH；false 表示这条记录走了其他解析路径。看到 false 时，还要结合系统和代理设置才能确定是谁回答的。查不到域名时，先保留这个结果，单凭空白无法判断走了哪条路。Firefox 的 DoH 实现说明 诊断表读取记录的源码 记录来源的源码

根据结果决定下一步

  • 命令行和软路由都能查，Firefox 的记录显示 true。 先查浏览器当前的 DoH 服务商。在自己管理的家庭网络上，如需对照，可以记下原设置，短暂关闭 Firefox 的 DoH，再清理浏览器的 DNS 缓存并重试同一域名。测完恢复原设置。关掉后恢复访问，只能说明这次访问受设置切换影响，可以沿浏览器解析这条线继续查。Mozilla 的保护级别说明
  • 直接问软路由也查不到。 先确认用的是实际提供 DNS 服务的地址，再查看软路由的 DNS 转发设置和相关日志。如果启用了代理客户端的 DNS 接管或浏览器代理的远端解析，也记下当前模式。它们可能参与查地址，尤其在诊断页找不到目标域名时，查对应客户端的日志比继续切换浏览器选项更有用。dnsmasq 的转发说明
  • 命令行和浏览器都有地址，网页仍打不开。 记下网页提示，再看代理客户端的连接记录里有没有这个域名、走的是哪个节点。DNS 已经给出了地址，后面还可能遇到连接超时或证书错误，按实际提示往下查。
