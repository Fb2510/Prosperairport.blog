代理启动提示端口被占用，怎么找到占用程序？

阿旺2026-11-11— 次阅读
客户端教程

Windows 上的代理客户端启动时提示端口被占用，先记下日志中的本机地址和端口，再用 PowerShell 查出正在监听的程序。确认程序后，可以退出暂时不用的那一个，或在客户端设置中为两个程序分配各自的端口。

从日志里找本机代理端口

端口是一台设备上用于收发连接的编号。采用 Mihomo 内核的 Clash 类客户端，可以设置本机 HTTP、SOCKS 或混合代理端口。混合端口可以接收 HTTP 和 SOCKS5 代理请求。查看日志时，先定位报错的本机代理入口。 Mihomo 代理端口文档

以下示例使用 127.0.0.1:7897。127.0.0.1 指本机，7897 是端口号。查询时请换成自己日志中的实际端口。Windows 的 10048 错误表示尝试使用的套接字地址已被占用，判断时要结合协议、本地地址和端口。 Microsoft 的 Windows 套接字错误说明

查出正在监听的程序

在支持 Get-NetTCPConnection 的 Windows PowerShell 中运行下面的只读查询。Listen 表示该端口正在等待 TCP 连接。 Microsoft 的 Get-NetTCPConnection 文档

Get-NetTCPConnection -LocalPort 7897 -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess

结果中的 OwningProcess 是进程编号，也叫 PID。假设查询结果为 4321，用下面的命令查程序名称。请用实际查到的 PID 替换示例数字。 Microsoft 的 Get-Process 文档

Get-Process -Id 4321

有多条记录时，把每条的本地地址和 PID 与报错一起核对。若进程已经退出，可以在报错再次出现时重新查询，获得当时的监听记录。

按程序用途处理

  • 如果查到的是自己启动且暂时不用的另一个代理客户端，从软件菜单退出它，再运行一次端口查询。确认相关监听已释放后，重新启动要用的客户端。
  • 如果两个程序都需要运行，按各自客户端的文档设置不同的本机代理端口，并记录原来的值。软件若手动填写过代理地址，也要检查它是否仍指向旧端口。
  • 如果看到系统进程、单位管理的程序或不认识的名称，先保留地址、端口、PID 和报错，由维护人员确认程序用途。

用启动日志和实际访问验收

重新启动后，检查这次启动日志，再查询当前端口的监听记录，确认对应的是准备使用的客户端或其内核。接着用已配置代理的浏览器打开平时需要代理的网页，检查新请求是否正常。

如果查询时没有匹配的 TCP 监听项，先重现一次报错并核对地址、协议和端口。若日志给出 10013，微软将它归为访问权限错误，排查时应保留完整原文并参照该客户端的说明。 Microsoft 的 Windows 套接字错误说明

资料核对日期为 2026 年 11 月 11 日。文中的端口和进程编号均为演示值。
