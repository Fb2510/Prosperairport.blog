软路由改了设置，电脑还在用旧参数

阿旺2026-10-26— 次阅读
软路由与排障

软路由修改了网关或 DNS 的下发设置，有的设备恢复了翻墙，电脑却仍然不通，可以先查看电脑实际拿到的参数。路由器页面保存成功，并不等于每台设备已经收到了新设置。

本文以自己管理的家庭网络和 Windows 11 电脑为例，先检查 IPv4 参数。网关是电脑把访问交出去的下一站，DNS 则帮助电脑把网站名称查成地址。

先写清楚，电脑应该收到什么

记录当前接线方案中，电脑应使用的网关和 DNS，再与电脑上的实际结果比较。不要直接照抄别人教程里的地址。

家里若由另一台主路由负责分配参数，就要核对那台设备实际下发的内容。使用 dnsmasq 的 OpenWrt 配置中，LuCI 提供了向客户端下发 DNS 的 DHCP 选项；这是给终端的设置，与软路由自己如何查询 DNS 需要分开看。OpenWrt 项目中的相关说明

还有一种正常情况：电脑一直把软路由当作 DNS，你只更换了软路由的上游 DNS。这时电脑仍显示软路由地址，可能正符合原来的设计。dnsmasq 可以接收客户端查询，再向上游 DNS 转发。dnsmasq 官方工作说明

所以，要比较的是“终端按计划应该收到的参数”，不能要求电脑显示软路由里填过的每一个地址。

为什么设置可能没有马上跟着变

DHCP 可以理解成向设备分发上网参数的服务。自动取得的地址通常带有租期，设备会按规则申请续租或重新获取配置。保存服务器设置后，不能仅凭时间先后就确认客户端已经更新。DHCP 的租用与更新机制

网关和 DNS 也是 DHCP 可以提供的参数，并非只分配一个 IP 地址。DHCP 参数说明

不过，“仍使用旧参数”只是一个待核对的方向。电脑也可能手动保存了地址，或正在连接另一张网卡对应的网络。

在电脑上查看当前结果

在开始菜单搜索并打开“命令提示符”，输入：

ipconfig /all

找到当前联网的 Wi-Fi 或以太网条目，先看以下几项：

  • IPv4 地址：是否符合家里的地址规划。
  • 默认网关：是否仍是修改前的地址。
  • DNS 服务器：是否符合这台电脑应使用的设置。
  • DHCP 是否启用，以及显示的 DHCP 服务器是否为预期设备。

网卡就是电脑用于联网的接口。输出里可能同时出现无线、有线和代理软件的虚拟接口，不要拿未连接的接口或虚拟网卡数值，代替当前家庭网络连接。

Microsoft 将 /all 定义为显示各接口的完整配置，相关命令说明适用于 Windows 11。官方命令说明

同时检查 Windows 网络设置里有没有手动指定 IP 或 DNS。不要只看到 DHCP 已启用，就跳过自己曾经手动改过的 DNS 项。自动与手动设置说明

自动取得参数时，做一次更新再比较

确认当前连接使用自动取得 IP 后，可以在自己管理的电脑上，以管理员身份打开命令提示符，更新对应网卡的 DHCP 配置。

下面是示例命令，其中 Wi-Fi 必须替换成刚才输出中自己的网卡名称；名称带空格时保留引号：

ipconfig /renew "Wi-Fi"

Microsoft 说明，/renew 用于更新 DHCP 配置，只适用于设置为自动取得地址的接口。参数适用条件

更新可能影响正在使用的连接，避开通话、远程控制或重要传输时操作。完成后再次查看同一网卡的参数，并测试普通网页和一个平时需要代理访问的网站。

重点看网关、DNS 与预期是否一致。电脑的 IPv4 地址没有变化，并不能单独证明更新失败。

如果原来使用手动配置，续租不能替你修正手动填入的旧地址。先记录原值，再按自己的接线方案检查；不要为了套用命令，把原本有用途的固定设置全部改成自动。

清 DNS 缓存，解决的是另一件事

ipconfig /flushdns 清理的是系统保存的域名查询结果；ipconfig /renew 更新的是 DHCP 配置。两者的用途在 Microsoft 文档中分别列出。

如果电脑仍指向错误的网关或 DNS，仅清缓存不能代替修正这些参数。先核对设置，再根据具体的解析错误决定是否需要处理缓存。
