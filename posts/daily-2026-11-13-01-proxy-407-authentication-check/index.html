代理提示 407，该填哪个账号？

阿旺2026-11-13— 次阅读
客户端教程

打开网页时看到 407 Proxy Authentication Required，先确认浏览器或应用连的是哪一个代理。407 表示这次请求需要通过代理的身份验证。这里说的「代理」是替应用转发请求的程序或服务器，它可以是电脑上运行的客户端，也可以是局域网或单位提供的代理。遇到 407 时，先找到要求验证的入口，再核对账号。HTTP 标准对 407 的说明

看应用把请求发给了谁

  1. 先看出错应用自己的代理设置。如果它有手动设置，记下代理类型、地址和端口。如果它跟随系统，Windows 11 可以到「设置 → 网络和 Internet → 代理」查看。记下正在使用的方式。手动代理可直接查看地址和端口，设置脚本或自动检测则需要向提供方核对实际使用的代理。微软的 Windows 代理设置说明
  2. 把地址和端口与预期的入口对照。127.0.0.1 代表这台电脑，局域网内的代理则需要填那台设备提供的地址。用 Mihomo 内核的 Clash 类客户端时，可查看生效配置里的 HTTP 或混合端口。混合端口可以接收 HTTP 和 SOCKS5 请求，只有 SOCKS 的端口要用相应的代理类型。Mihomo 的代理端口说明
  3. 确认入口属于你认识的程序或服务，再使用对应的代理凭据。如果这个入口是自己搭的，检查生效配置；如果是单位提供的，向管理员核对。订阅链接、机场面板密码和网站登录密码各有用途。只有代理服务明确指定的凭据才填进代理认证窗口。

用一次不带密码的请求做对照

如果原来用的是自己管理的 HTTP 或混合端口，可以在 Windows 的「命令提示符」里做一次对照。把示例里的 127.0.0.1:7890 换成你核对过的地址和端口。命令只测试一条请求，保留原来的系统和客户端配置。curl 的代理选项 curl 的代理例外选项

curl.exe -q --proxy http://127.0.0.1:7890 --noproxy "" --head --max-time 10 https://example.com/
  • 提示 407。 这条请求也遇到了代理认证。若入口由自己管理，可以查看同一时间的代理日志，核对是本地入口要求认证，还是转发过程中的代理返回了提示。Mihomo 配置中的 authentication 用于设置代理用户名和密码，skip-auth-prefixes 列出可免验证的来源地址段。同一端口在本机能用、另一台设备却提示 407 时，可以核对两边的来源地址是否落在不同范围里。Mihomo 的认证说明
  • 测试成功，原应用还提示 407。 先确认原应用的代理地址、端口、类型和测试一致。即便入口一致，测试结果也只覆盖这个网址和这条请求。再记录原应用的报错时间，用客户端日志核对当时选中的规则和线路。
  • 提示连接被拒绝或超时。 这次没有拿到 407，先核对地址、端口和代理程序是否正在运行。把两种报错各自记下来，继续排查时更容易对上日志。

向管理员或服务商反馈时，提供报错时间、应用名称、代理类型和经遮挡的错误截图。密码、完整订阅链接和含认证信息的配置留在自己手里。
