退出 Clash 后，普通网页也打不开？检查 Windows 代理残留

阿旺2026-10-10— 次阅读
客户端教程

退出 Clash 后，连平时不用翻墙就能打开的网页也失败，可以先检查 Windows 的代理设置。有时客户端已经停止，系统却仍把浏览器请求交给它，普通上网就会受到影响。

本文面向 Windows 电脑，操作入口以 Windows 11 为例，Windows 10 的按钮位置可能略有不同。Clash 类客户端界面各不相同，下文引用的具体故障说明来自 Clash Verge Rev 项目。

为什么打开 Clash 就恢复，退出又断网？

可以把系统代理理解成一条指路设置：让遵循它的软件先把请求送到代理入口，再由客户端处理。

电脑上的代理入口可能写成 127.0.0.1，指的是这台电脑本身；后面的端口要与客户端设置对应。端口并非所有客户端都一样，不要为了排查而照抄别人截图里的数字。

如果客户端异常退出，指路设置可能没有同时清除。Clash Verge Rev 的官方常见问题列出了这种情况，并建议检查 Windows 的手动代理开关。查看项目的 Windows 故障说明

这是一种待验证的原因。单凭“打开客户端才有网”，还不能排除其他网络设置的影响。

第一步：选对测试网页，记录当前设置

先打开两个你平时可以直接访问的普通网站，记下它们是否都失败。需要翻墙的网站在退出代理后打不开，本身不能说明电脑断网。

再检查客户端是否仍在托盘中运行，确认你做的是退出，还是仅关闭了主窗口。操作前，可以记录系统代理地址、端口和开关状态，方便恢复。

如果电脑由单位统一管理，先确认这条代理的用途；本文的关闭操作针对你自己为代理客户端设置的入口。

第二步：关闭指向已退出客户端的手动代理

在 Windows 设置中按下面的顺序检查：

  1. 打开“网络和 Internet → 代理”。
  2. 找到“手动代理设置”中的“使用代理服务器”。
  3. Windows 11 通常需要点旁边的“设置”，才能查看地址、端口和开关。
  4. 确认它对应刚才退出的本地客户端后，关闭“使用代理服务器”，并保存。
  5. 重新打开测试网页，观察是否恢复。

微软的代理设置文档适用于 Windows 10 和 Windows 11，并分别说明了手动代理、自动检测和设置脚本的入口。查看微软官方操作说明

这一步只处理已经确认的手动代理。看到另一个陌生地址时，先查是谁设置的，不要随意清空。

第三步：手动代理已关，还要看什么？

先看是否使用了设置脚本。 Windows 也支持通过脚本决定哪些访问走代理。如果你之前为客户端配置过脚本，核对其地址；确认它属于这套已停用的代理后，再暂时关闭“使用设置脚本”做对比。自动检测是另一项设置，不必为了排查把所有开关都改一遍。

再看客户端是否启用了 TUN。 TUN 使用虚拟网络接口接管流量，处理路径与手动系统代理不同。仅关闭 Windows 手动代理，不能证明 TUN 已经停止；可以在客户端仍能打开时，按它的文档暂停 TUN 后比较。查看 Mihomo 的 TUN 配置说明

如果只是一款浏览器失败， 再检查该浏览器的代理扩展或独立设置。暂时停用你自己配置的代理扩展，重新测试；每次只动一项，保留对比结果。

用结果判断下一步

观察到的结果 优先检查的方向
关闭残留手动代理后，普通网页恢复 系统代理没有随客户端退出而清除
手动代理本来就关闭，暂停 TUN 后恢复 TUN 及相关路由配置
一款浏览器失败，另一款能打开同一网页 浏览器自己的代理或扩展
更换手机热点后仍失败 继续检查电脑设置，记录已做过的对比
同一网络上的其他设备也无法普通上网 路由器、宽带及上游网络

这些结果用来缩小范围，不是一次测试就能确定的结论。代理设置处理后仍失败，可以带着记录继续排查，先别连续重装客户端或重置全部网络。

恢复后，再检查一次正常退出

重新运行客户端，按日常方式启用代理，分别测试普通网页和需要代理的网站。准备退出时，先关闭本次使用的代理入口，再完成退出，观察 Windows 设置是否符合预期。

如果每次退出都会复发，记录客户端名称和版本、Windows 版本、退出前后的代理状态，以及是否开启 TUN。向项目反馈时附上经过遮挡的日志，完整订阅链接和节点密码不要公开。

资料核对日期：2026 年 10 月 10 日。
